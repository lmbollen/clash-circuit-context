# ADDED
A recording can keep its values in memory (`spill = InMemory`), so that
nothing is written to disk but the waveform. With `spill = OnDisk`, a run that
is stopped (a cancelled test, a killed process) keeps its spill file, which
now describes itself: `recoverWaveform` (or `recoverRecording`) writes the
waveform of what the run recorded. A cancelled run keeps everything it
recorded, and so does a killed one (SIGKILL, out of memory, a crash): the
spill file is mapped into memory, so a value is in it as soon as it is
recorded. Only a crash of the machine can lose the newest values. The file's
disk space is reserved ahead, up to 64 KiB per signal: a full disk stops the
recording, not the run, with a message, and the waveform ends where the
recording stopped. Where the file cannot be mapped (some network file
systems, Windows, or `CCC_SPILL_NO_MMAP=1`), it is written 64 KiB per signal
at a time instead, and a killed run loses the values not written yet. A run
whose waveform cannot be written keeps its spill file too, and says where it
is.
